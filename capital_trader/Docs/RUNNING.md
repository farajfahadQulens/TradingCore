# Running the Capital.com Async Trading Platform

This document explains how to get the project up and running on your machine.
It assumes you have **Python 3.11+** installed and a Unix‑like shell.

---

## 1. Prerequisites

| Tool | Why we need it |
|------|----------------|
| `git` | To clone the repository (if you haven’t copied the folder already). |
| `python >=3.11` | The codebase uses modern async features and Pydantic 2. |
| `virtualenv` (or `venv`) | To keep dependencies isolated from your system Python. |
| `pip` | To install the packages listed in `requirements.txt`. |
| **Optional** – Docker & Docker‑Compose | For containerised deployment (see the Docker section later). |

---

## 2. Clone the repository (skip if you already have the folder)

```bash
git clone <repo‑url> capital_trader
cd capital_trader
```

---

## 3. Create & activate a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate   # on Windows use .venv\Scripts\activate
```

You should now see the prompt prefixed with `(.venv)`.

---

## 4. Install dependencies

First, upgrade `pip` (recommended):

```bash
python -m pip install --upgrade pip
```

Then install everything:

```bash
pip install -r requirements.txt
```

You will see a list of packages being downloaded – FastAPI, aiohttp, SQLAlchemy async, etc.

---

## 5. Configure environment variables

A template named `.env.example` is provided. Copy it to `.env` and fill in your real values:

```bash
cp .env.example .env
nano .env   # or any editor you prefer
```

The file must contain at least:

```text
CAPITAL_API_KEY=        # optional – can be empty if you’ll log‑in with username/password
CAPITAL_USERNAME=your_user
CAPITAL_PASSWORD=your_pass
ENVIRONMENT=demo        # or "prod"
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost/trading
LOG_LEVEL=INFO
```

*If you don’t have a PostgreSQL server yet, you can run one via Docker (see step 9).*

---

## 6. (Optional) Spin up a PostgreSQL database with Docker

```bash
docker run -d \
    --name pg \
    -e POSTGRES_USER=postgres \
    -e POSTGRES_PASSWORD=postgres \
    -p 5432:5432 \
    postgres:16-alpine
```

The `DATABASE_URL` in your `.env` already points to this container (`localhost:5432`).
The first time the app accesses the DB it will automatically create the tables (`positions`, `orders`, …) based on the SQLAlchemy models.

---

## 7. Start the FastAPI server (which also starts the background orchestrator)

From the project root, run:

```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Typical output:

```
INFO: Started server process [...] 
INFO: Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
INFO: Application startup complete.
```

The orchestrator will now:
1. Load configuration & set up JSON logging.
2. Authenticate with Capital.com (or attempt to – you’ll see back‑off logs if the placeholder URL is still used).
3. Perform an initial reconciliation of local DB vs. broker state.
4. Open the market WebSocket and begin feeding ticks into `price_queue`.
5. Switch the trading mode to `LIVE_TRADING` once everything is ready.

---

## 8. Verify the service

Open another terminal (or keep the same one) and run a couple of curl commands:

```bash
curl http://localhost:8000/api/health
curl http://localhost:8000/api/positions
```

You should receive JSON responses. `positions` will be an empty array on a fresh DB.

---

## 9. (Optional) Run everything via Docker‑Compose

A minimal `docker-compose.yml` is already present. To launch the full stack:

```bash
docker compose up --build
```

The compose file defines two services:
- `app` – builds the image from the repo, runs the same command as step 7.
- `postgres` – the DB container used by `DATABASE_URL`.

You can then hit `http://localhost:8000/api/health` from your host machine.

---

## 10. Next Development Steps

- **Replace placeholder URLs** in `app/broker/client.py` and `app/broker/websocket.py` with the real Capital.com endpoints.
- **Implement an order‑execution consumer** that subscribes to `EventBus` for `OrderSubmitted` events, calls the broker API, and updates the `Order` model.
- **Add metrics**: expose `/metrics` using `prometheus_client` and register counters (e.g., order submissions, reconcilations).
- **Write unit & integration tests** under `app/tests/` using `pytest‑asyncio`.
- **Extend the API** with POST endpoints for creating orders, managing alerts, etc.

---

## 11. Cleaning Up

When you are done, stop the server with `Ctrl‑C`. If you started a Docker DB, bring it down with:

```bash
docker compose down   # or docker stop pg && docker rm pg
```

Delete the virtual environment if you no longer need it:

```bash
deactivate
rm -rf .venv
```
